## 评审摘要

| 维度 | 现状 | 重构后 | 主要风险 |
|---|---|---|---|
| 首屏信息 | 四段状态条 + 常驻表单 + 目录统计 + 逐行成功标签 | 四块：连接/状态、周期、列表、添加入口 | 改动面最大，需分步落地 |
| 点位查找 | 238 行平铺，无搜索无分页 | 搜索 + 问题筛选 + 25 项/页 | 前端过滤的规模上限（§2.7） |

| 提示 | 常驻说明 + 加载即弹 toast | 按节点出现，一次一条 | 现有测试断言需同步调整（只改查询方式，不放宽断言） |

## 一、背景与边界

### 1.1 背景

A 组已完成局部修复，且修复已在 `main`：

| 已修问题 | 落点 |
|---|---|
| 未选变量不报虚假错误 | `apps/mesa-web/src/components/NckPointFields.tsx:307-309`、`:362-364` |
| 未知字段拒绝编辑与保存（表单与守卫同源） | `apps/mesa-web/src/descriptorCompatibility.ts:139-155`、`EndpointAcquisitionPane.tsx:723-741` |
| 中文取值（定义 label 优先 `zh`） | `apps/mesa-web/src/nckPointModel.ts:39-45` |
| 通用「字段标签 + 值」摘要 | `apps/mesa-web/src/pointSummary.ts:127-137` |
| 草稿与已保存区分 | `apps/mesa-web/src/acquisitionDraft.ts:43-47`、`EndpointAcquisitionPane.tsx:1006-1023` |

但页面本身仍然难用：**信息过多、提示常驻、点位不好找、编辑保存费劲**。本稿只解决**页面信息架构**，不解决契约层面的驱动耦合。

### 1.2 必须明确声明：本稿不做驱动解耦

> 本稿**不做驱动解耦**。现有 `driver_id` / 协议字段名 / 资源 ID 的专用判断**仍然存在**，本稿**不声称已解耦**，也**不把已有耦合包装成已完成**。
>
> 解耦属 **B 组**（权威准入、身份预览接通、质量码命名空间），另稿设计。

本稿只做一件事：把驱动相关的**判断**留在页面层既有分支里，把**展示**抽成不含驱动判断的通用组件。判断本身没有被消除，只是不再散落在表格、抽屉、搜索、分页里。

### 1.3 架构约束（硬性）

1. **通用组件零特判**：本稿涉及的所有通用组件（表格、抽屉、搜索、分页、草稿、保存区）**不得新增** `driver_id`、协议字段名、资源 ID 特判。判定口径见 §2.8。
2. **校验保护一条不减**：以下守卫在重构后必须原样存在，且仍由页面层/既有模块执行，不下沉到通用组件：

| 守卫 | 现落点 | 重构后 |
|---|---|---|
| 服务端身份预览（Key 唯一来源） | `NckPointFields.tsx:209-290`、`nckCatalog.ts:597-602` | 不变 |
| 输入变更后旧 Key 立即失效 | `NckPointFields.tsx:292-296`、`:197-199` | 不变 |
| 保存前重新核验 | `EndpointAcquisitionPane.tsx:769-779` | 不变 |
| 保存后回读确认（NCK） | `EndpointAcquisitionPane.tsx:835-851` | 不变 |
| 完整 Schema 保存守卫 | `descriptorCompatibility.ts:139-155`、`EndpointAcquisitionPane.tsx:739-741` | 不变 |
| 任务快照门 / 不可安全编辑门 / scope 准入门 | `EndpointAcquisitionPane.tsx:731-734`、`:745`、`:747-753` | 不变 |

3. **保存语义不变**：仍是全量快照替换（Stop → PUT → 回读），不改后端契约、不改 `PUT /tasks/{endpoint}` 请求体形状。

### 1.4 六项固定范围（不扩大）

| # | 范围 | 本稿对应章节 |
|---|---|---|
| 1 | **默认页面精简**：只保留连接、采集配置、点位列表、添加入口 | §2.2、§2.5 |
| 2 | **提示按节点出现**：字段错误在编辑时；中断说明在有修改且运行中时；保存结果在执行后；技术详情主动展开 | §3 |
| 3 | **紧凑点位列表**：搜索已有点位、分页、问题筛选、取消逐行重复的成功标签 | §2.7、§5.2 |
| 4 | **抽屉式添加与编辑**：保持列表位置；「确认修改」只是更新草稿 | §4.1、§4.2 |
| 5 | **固定保存区**：有修改才出现；显示变更摘要、放弃修改、实际保存动作 | §2.3、§4.4 |
| 6 | **隐藏无关能力**：不支持的功能不占默认页面空间 | §2.5、§3 |

**明确不做**：驱动解耦、后端契约变更、事件订阅改版、拖拽排序、批量编辑、虚拟滚动（238 行用分页足够；>1000 行另立项，与 `pr-d1-quality-code-visibility-design.md:466` 同一结论）、权限与审计。

## 二、结果 1：默认页面布局

### 2.1 布局原则

- **一屏四块**：连接与运行状态、采集周期、点位列表、添加入口。除此之外默认不出现第五块。
- **默认安静**：成功、正常、已保存都是默认态，不占视觉；只有**需要动作**的信息才出现。
- **位置稳定**：任何编辑动作都不把用户从当前页/当前行带走。
- 线框为示意，列宽可调；`⋯` 表示行内「更多」。

### 2.6 点位摘要必须保留辨识信息

精简**不等于**把所有行变成无法区分的「原生点位」。规则：

1. **行 = 当前可编辑单元**：NCK 为「一个点位」，非 NCK 为「一条资源选择（可含多个输出）」。两者共用行组件，但**不声称是同一模型**。
2. **标题**：优先 Descriptor / 定义目录的 `label`（中文优先，`nckPointModel.ts:39-45`），缺失退回 `variable_id` / `resource_id` / 「原生点位」。**不得按地址编造业务名**（沿用 `nckPointDisplay.ts:1-12` 的硬约束）。
3. **摘要**：复用 `pointSummary`（`pointSummary.ts:127-137`）的「标签 值」；没有可读参数时回退 `point_key`（`:136`），不得留空。
4. **原生点位**：标题固定「原生点位」时，**必须同时显示五段结构化地址**（`nckPointDisplay.ts:64-69`，如 `C / 1 / 122 / 5 / 1`）。238 点里 235 个是原生点位，地址就是唯一辨识信息，不得截断成只剩名称。
5. **两行即可判定**：任意两行在同一页内必须能靠「名称 + 摘要」区分；做不到时摘要补 `point_key` 尾段（仍在技术详情之外）。

### 2.7 搜索 / 筛选 / 分页规则

| 能力 | 规则 |
|---|---|
| 搜索 | 匹配 **标题、地址/摘要、标识**（`point_key` / `variable_id` / `resource_id`）三段，包含匹配、大小写不敏感；输入即过滤 |
| 筛选 | 全部 / 有问题（N）/ 已修改（M）；N、M 来自当前草稿，不是服务端 |
| 分页 | 默认 25 项/页；页码与筛选、搜索联动；切换页不清草稿 |
| 位置保持 | 抽屉关闭后回到**同一页 + 同一滚动位置**（记录 `scrollTop`）；保存后行数变化时落到「包含原行号」的页 |
| 空态 | 搜索无结果时给「没有匹配的点位，可改用标识搜索」+「清除搜索」，不显示空表 |
| 规模 | 前端过滤对 238 行足够；**>5000 行需服务端搜索**（待确认，不在本稿范围） |

每页 25 与全局数据页 20（`apps/mesa-web/src/pages/GlobalDataPage.tsx:307`）不一致，是否统一为 20 **待确认**。

数据来源：页面层保留现有分支（`deviceModel.ts:249-251` 的 `isNckDriver`、`EndpointAcquisitionPane.tsx:208`），把两条数据路径归一成 `PointRow = { rowId, title, summary, state, issue? }` 后传给通用组件。**这一步不是解耦**：驱动判断仍然存在，只是不再进入展示组件。

可检验口径：通用组件文件内不得出现 `driver_id` / `isNckDriver` / `nck.points.v1` / `mesa.resources.v1` / 字面量 `"variable"`，也不得 import `nckPointModel` / `nckCatalog` / `nckTaskBinding`。

### 2.9 行级元素预算

| 元素 | 默认行 | 问题行 | 已修改行 |
|---|---|---|---|
| 名称 | 1 行 | 1 行 | 1 行 |
| 摘要 | 1 行（含地址） | 1 行（含地址） | 1 行（含地址） |
| 状态标记 | 无 | 1 个（色点 + 短文案） | 1 个「已修改」 |
| 操作 | 编辑 · ⋯ | 编辑 · ⋯ | 编辑 · ⋯ |
| 技术详情 | 不渲染（收在 ⋯） | 不渲染（收在 ⋯） | 不渲染（收在 ⋯） |

规则：

- 单行最多 **3 个可交互元素**（编辑、更多、冲突时的「查看已有项」）；
- 行内不得出现常驻 `Tag`、不得出现 JSON、不得重复展示 `point_key`（它只属于技术详情）；
- 问题行与已修改行**可以同时存在**，但两者标记不叠加成两个标签，用「已修改 · 有问题」一条短文案表达。

## 三、结果 2：信息展示时机表

### 3.1 完整时机表

| 信息 | 何时展示 | 展示位置与方式 |
|---|---|---|
| 必填、格式、范围错误 | 字段失焦或用户点击确认时 | 字段下方一行红字；同字段只留最新一条；不在页面顶部汇总 |
| 字段之间的约束错误 | 输入足够完整并完成校验后（非逐键） | 抽屉底部汇总区，列出「字段 → 原因」；点击定位到字段 |
| 变量配置说明 | 用户选中该变量后 | 抽屉内选中项下方一行；未选中不出现 |
| 高级字段 | 用户主动展开「高级设置」时 | 抽屉内折叠区，默认收起；折叠态只显示计数「高级设置（3）」 |
| 身份核验中 | 用户输入已具备核验条件时 | 身份行内联「正在核验…」，不阻塞其它输入 |
| 身份核验失败 | 收到当前输入对应的失败结果时 | 身份行内联红字 + 原因码；输入一变立即清除（`NckPointFields.tsx:292-296`） |
| 重复点位 | 添加或修改造成冲突时 | 字段旁提示 + 「查看已有项」，跳到列表并高亮该行 |
| 已有配置存在问题 | 加载后确认问题确实存在时 | 列表上方**一条摘要**「3 个点位需要处理」，点击筛选/展开明细 |
| 未保存修改 | 用户确认添加、编辑、移除或修改周期后 | 底部固定保存区出现，显示变更摘要与计数 |
| 保存会中断采集 | 有修改，且当前连接正在运行时 | 保存区内一行说明；无修改时不出现 |
| 保存进度 | 用户点击保存后 | 保存区按钮 loading + 步骤文案（停止 / 写入 / 核验 / 恢复） |
| 保存失败 | 对应步骤失败时 | 保存区**持续展示**错误 + 下一步动作（重试 / 重新核对 / 查看诊断）；草稿保留 |
| 保存成功 | 回读确认后 | **一次简短通知**，同时清除未保存标记、保存区收起 |
| 技术详情 | 用户主动点击详情时 | 抽屉/行「⋯」里的折叠区：`point_key`、原始参数 JSON、定义版本、身份来源 |
| 实际读取异常 | 已获得真实运行结果时 | 采集页只在点位行显示问题标记；明细统一在「数据」页，避免各页重复报警 |
| 页面级加载失败 / 配置损坏 | 加载完成且确认失败时 | 页面内一条说明影响 + 动作：「配置加载失败，暂时无法编辑。［重试］」 |

### 3.2 两条原则

- **正常信息默认安静，异常信息直接关联处理动作。** 「已保存」「校验通过」「格式正确」都是默认态，不占视觉；出现的信息必须能点、能定位、能继续。
- **用户还没有输入或提交时，不先摆出一屏错误。** 未选变量不渲染字段错误（沿用 `NckPointFields.tsx:307-309`、`:362-364`）；抽屉未打开时页面无字段级错误。

### 3.3 但：真实问题不能隐藏

加载失败、已有配置损坏、身份核验不通过等**真实问题不得折叠进技术详情**：

- 用一句话说明**影响**与**下一步**（「配置加载失败，暂时无法编辑。［重试］」）；
- 保留原始错误码与响应，供排查时展开（`EndpointAcquisitionPane.tsx:1481-1495` 的 `issues` 原样展示是正确形态，保留）；
- **无需默认解释**快照、接口路径、内部错误码——这些只在技术详情里出现。

## 四、结果 3：添加—编辑—保存与失败恢复

### 4.1 添加流程

```

   → 写入页面草稿 → 抽屉关闭 → 回到原列表位置
```

| # | 步骤 | 交互细节 | 复用/新增 |
|---|---|---|---|
| 1 | 点「添加点位」 | 抽屉从右侧打开，不遮挡列表标题与页码 | 新增（现状为常驻表单 `EndpointAcquisitionPane.tsx:1152-1182`） |
| 2 | 按驱动声明的入口 | **沿用现有** `resource_selection_methods`（`types.ts:88`、`ResourcePickerAntd.tsx:109-110`）；只渲染声明且可用的入口 | 不改契约，不新增特判 |
| 3 | 可搜索选择器 | 变量名 / ID / 资源名；选中项高亮；无结果给提示 | 复用 `NckPointFields.tsx:414-452` 的搜索 |
| 4 | 选中后才出现必要字段 | 未选时不渲染 Target/Arguments，也不显示字段错误 | 复用 P0-1 语义 |
| 5 | 高级字段默认收起 | 「高级设置（N）」折叠；原生 12 字段、decode/count 等在内 | 新增折叠（现状平铺 `NckPointFields.tsx:514-643`） |

### 4.2 编辑流程

```
点行「编辑」
   → 抽屉立即打开并带入配置（字段已就绪，不重新拉目录）
   → 修改（输入一变，旧身份 Key 立即失效并重新核验）
   → 点「确认修改」
   → 只更新草稿（不发任何写请求）
   → 抽屉关闭，返回原列表位置
   → 该行标记「已修改」
```

| # | 步骤 | 关键约束 |
|---|---|---|
| 1 | 点行「编辑」 | 抽屉立即打开；`point_key` 不预填为可提交值，仍以服务端预览为准 |
| 2 | 修改 | 旧 Key 失效是**渲染期判定**，不等响应（`NckPointFields.tsx:292-296`） |
| 3 | 「确认修改」 | 只更新页面草稿；不 PUT、不 stop、不 start（复用 `replacePoint` `EndpointAcquisitionPane.tsx:620-627`） |
| 4 | 抽屉关闭 | 返回同页、同行、同滚动位置 |
| 5 | 行标记「已修改」 | 与保存区计数同源；撤销修改后标记消失 |

编辑不改变「可编辑性」判定：目录里已不是最新 revision、或已失去 `collect` scope 的点位，仍然只能移除后重配（`EndpointAcquisitionPane.tsx:1272-1288` 的 `editableGate` 原样保留）。

### 4.3 抽屉内的唯一说明

> 确认后加入页面草稿，保存配置后生效。

除这一句外，抽屉内不再放教程、流程说明、接口说明；错误、核验状态按 §3.1 的时机出现。

### 4.4 保存

| 当前情况 | 保存区动作 | 说明 |
|---|---|---|
| 已停止 | 「保存配置」 | 保存后保持停止，不自动启动（沿用 `deviceModel.ts:481-485`） |
| 运行中，选择恢复运行（**默认**） | 「保存并恢复采集」 | 停止 → 写入 → 回读 → 启动 |
| 运行中，选择保持停止 | 「保存并停止采集」 | **次级选项**，默认不选，不弹二次确认 |
| **运行状态无法确认** | **禁止保存**，显示「刷新状态」 | 未知状态下不得推断「已停止」，也不得替用户停止/启动 |
| **没有实际修改** | 保存区不出现；任何入口都不得发起 PUT | 与 `NO_CHANGES` 一致（`endpointSavePlan.ts:180-186`） |

执行顺序与结果落点沿用现有生命周期状态机（`deviceModel.ts:474-494`、`LifecycleOutcome:462-467`），保存区只负责**展示**它给出的 outcome，不自行解释。

不为正常保存增加多层确认弹窗：运行中的「会中断」说明本身就是确认，按钮文案即动作。

### 4.5 失败恢复

| 问题 | 面向用户的提示与操作 |
|---|---|
| 参数未填写 | 「请填写通道编号」，显示在字段旁，不弹窗 |
| 点位重复 | 「这个点位已经存在」，提供「查看已有项」 |
| 已有配置不能通过校验 | 「3 个点位需要处理」，提供筛选和编辑 |
| 保存前检查失败 | **自动定位第一个问题，不先停止采集** |
| 停止失败 | 「未能停止采集，已取消本次保存」，可重试（沿用 `deviceModel.ts:486-487`） |
| 写入后无法确认结果 | 「暂时无法确认保存结果」，提供「重新核对」（沿用 `EndpointAcquisitionPane.tsx:838-850` 的回读失败分支） |
| 保存成功但启动失败 | 「配置已保存，恢复采集失败」，提供「查看诊断」或「启动」入口（沿用 `:910-913`） |

### 4.6 关键规则

1. **错误详情保留原始代码与响应**，供排查时展开；面向用户的一行文案不暴露内部码。
2. **保存失败时保留草稿**：点位、周期、变更计数都不清空（现有 `saveIssues` 已原样保留，`EndpointAcquisitionPane.tsx:810`、`:866`）。
3. **配置已确认保存后，即使恢复运行失败，也不能继续显示成「配置尚未保存」**：基线必须在写入 + 回读确认后才刷新（`:854-858` 已是该口径），启动失败只影响「运行状态」这一项。
4. **成功提示只在确认完成时出现一次**，不重复：现在 toast（`:891`、`:897`）与常驻 `Alert`（`ApplyWithRestart.tsx:69-92`）同时出现，属重复，收敛为一次。

### 4.7 保存区状态机

| 状态 | 进入条件 | 展示 | 退出 |
|---|---|---|---|
| 隐藏 | 无修改 | 不占空间（页面底部无条） | 出现第一处修改 |
| 待保存 | 有修改、未保存 | 变更摘要 + 放弃修改 + 保存按钮（运行中含中断说明） | 保存 / 放弃 |
| 保存中 | 点击保存 | 按钮 loading + 步骤文案；输入与抽屉动作禁用 | 完成 / 失败 |
| 保存失败 | 任一步失败 | 错误条 + 下一步动作；草稿与行标记保留 | 重试 / 放弃 |
| 已保存 | 回读确认 | 一次简短成功，清除未保存标记，随后收起 | 自动 |
| 状态未知 | 运行态无法确认 | 禁用保存 + 「刷新状态」 | 刷新成功 |

补充：保存中禁止关闭抽屉或切换连接（避免「请求还在飞、页面已换」的错位）；失败后不自动重试，也不循环重试。
